# Eating animation / facial-expression handoff

Branch: `codex/fibu-eating` (built on approved proportions commit `113eb87`). This is a review delivery, not an app activation. Keep all local work, original skin art, old character resources, and Watch SCN. No Swift files or Xcode references are changed here.

## Files

- `Assets/Models/FibuEating/Fibu.Eat.usdz`: approved body with a new 2.8-second eating clip, six fitted mouth surfaces, two facial morphs, original 32-joint skeleton, and a replaceable bread placeholder. Its embedded skin is the cleaned original. The approved wave remains available in `Assets/Models/Fibu.Proportions.usdz`.
- `Assets/Models/FibuEating/EatingTextures/`: six RGBA mouth images, twelve separate skin derivatives without the painted smile, and individual original-resolution removal masks. Never substitute a skin that still contains the painted smile beneath an animated mouth.
- `timeline.json`: version 1, 30 fps, 85 samples inclusive of both endpoints; expressions, `cheekPuff`/`swallow` weights, food visibility, a single bite event, and food positions. Timeline is non-looping.
- `face-anchors.json`: version 1, 289 fitted vertices, approved body vertex IDs and barycentric anchors. Triangle fan order is from the USD source. Imported SceneKit geometry may reindex vertices at UV seams: remap to source vertex IDs before using these anchors. Directly imported skinned mouth meshes are preferable if verified.
- `skins.json`: source filenames/hashes and derivative mapping. Original and supplied skins use different mouth UV positions; each derivative has a registered mask. Leopard uses a local fur exemplar patch. Artist review of repaired pattern areas is still required. Local-only newer skins need corresponding derived versions.
- `validation.json`, `eating-preview.gif`, `expressions.png`, and angle/skin review images: technical and visual review evidence.
- `Assets/Blender/FibuEating/Fibu.EatingPreview.blend`: packed Blender review bake, frames 1–85. The original runtime rig and motion source are authored by `build.py`; see its README before exporting.

## Native integration after visual approval

1. Load the USDZ separately in SceneKit. Verify `Fibu_body`, `Face_smile`, `Face_open`, `Face_lick`, `Face_chew`, `Face_swallow`, `Face_happy`, and the two `CheekPuff`/`Swallow` targets. Preserve the complete skeleton hierarchy; do not concatenate a second character's skeleton or animate both skeletons simultaneously.
2. Verify the imported skeletal animation duration/time base, morph channels, expression visibility, and placeholder food track. USD time codes are 30/second; timeline times are seconds. The mouth switches discretely with exactly one visible expression. Never crossfade overlapping dark decals. If USD visibility/morph tracks are not imported, drive `isHidden` and the corresponding `SCNMorpher` weights from `timeline.json` on the SAME animation clock. Confirm target names/indexes rather than assuming importer order.
3. Skin selection changes only the BODY diffuse image to its NoSmile derivative. Leave mouth materials alone. Enable depth testing and depth writes as appropriate for the importer, use transparent mouth art, disable double-sided rendering, and verify no z-fighting/halo from front, both sides, above, and back. Face patches are already fitted/skinned; do not billboard them toward the camera. Mouth art should not cast a rectangular shadow.
4. Use the supplied clip as one one-shot action. Pause competing procedural arm/idle/walking/wave controllers during it, then restore normal control after the final pose. On interruption, clear facial targets, select `Face_smile`, remove the food prop, and restore controller ownership. Do not award food consumption twice from a completion callback plus a timeline bite event.
5. `PreviewFood` is replaceable and can be hidden. For an actual food asset, attach to `Hand_R_end` and sample `foodPositionHandLocal` (animated grip adjustment), or use the supplied skeleton-space position track after transforming to the character's skeleton space. These coordinates retain the original runtime scale; apply the character wrapper transform once. The local coordinates already include the animated hand inverse; do not apply it a second time. Native interpolation of scale to zero may shrink the placeholder over the last frame; the explicit timeline gives a discrete bite hide if preferred.
6. Inspect all existing local skins and the transition from idle/wave/walk into/out of eating. Check skin seams, grounding, front/side/back facial visibility, food contact, performance and import support in the iPhone simulator. Build both schemes and run relevant existing app checks if integrating. Keep Watch unchanged pending a separate resource/performance review.

The core body rest shape, topology, UVs, bone hierarchy/binds and skin weights match the approved proportions model. This does not prove native animation import. All 85 posed samples, facial fit, normal/weight data and package dependencies were checked in cloud; Xcode/SceneKit execution remains local.
